## 2. 사용자가 Preview 에서 볼 수 있는 것

기본형 자동변환(엑셀 선택 → 자동 AI 읽기)을 끝내면 **좌측 편집 패널 아래**에
`🧪 본문 글자 오버레이 진단(실험)` 접이식 줄이 하나 생긴다. **기본은 접혀 있다.**

펼치면 볼 것 **하나**: **원본 통이미지와 진단 미리보기를 나란히 보고 마스크 자국과 HTML 위치를 확인**한다.

- 본문에 실린 원본 통이미지 그대로
- 안전하다고 판정된 자리에만 **흰 사각 마스크 + HTML 글자**(heading·body·label 세 고정 스타일)
- 교체된 문구 / 원본 보존 / 진단 제외 목록과 **각각의 구체적 사유**
- GREEN · YELLOW · RED 신호

오른쪽 실제 상세페이지와 이미지 저장 결과는 **이 실험 전과 똑같다.**

### 정정 — "펼치지 않으면 성능 영향 없음"은 사실이 아니다

앞서 이 패널을 두고 *"펼치지 않으면 화면과 성능에 영향이 없다"* 고 적었는데, **정확하지 않다.**
정확한 표현은 이렇다.

> **기존 출력에는 연결되어 있지 않다. 다만 진단 계산과 Claude 응답 확장에 따른 소폭 영향은 있다.**

패널을 접어 두어도 변환 과정에서 다음이 **항상** 실행된다.

- 원본 파일별 크기 측정(`measureSourceSize`) 1회씩
- 글자 영역 검증·좌표 투영·흰 배경 픽셀 표본 추출(본문 파일 1장당 이미지 1회 로드)
- Claude 응답에 `bodyTextRegions` 항목이 늘어난 만큼의 **응답 토큰 증가**(호출 수는 1회 그대로)

바꾸지 않은 것은 **결과물**이다 — 본문 이미지·저장 파일·`ProductData` 는 그대로다.

## 4. 본선 적용 여부를 판단하려면 사용자가 확인할 한 가지

**대표 상품 몇 개를 실제로 변환해 진단을 펼치고, 흰 사각 마스크가 원본을 훼손하지 않았는지 본다.**

- 마스크가 글자만 정확히 덮고 제품·도해·선을 건드리지 않으면 → 본선 후보
- 마스크 자국이 배경과 티 나게 다르거나 그림을 갉아먹으면 → 흰 배경 기준(둘레 3px·RGB 245·98%)을 더 좁혀야 한다
- GREEN 이 거의 안 나오면 → 이 방식은 일부 상품 전용이고, 나머지는 원본 보존이 정답이다

## 5. 대표 4종 **fixture** 결과표

⚠️ **fixture 결과다. 실제 원본 유료 판독이 아니다.** 각 시나리오는 대표 4종의 *구조적 성격*
(원본 레이아웃 + 배경 성질)만 재현했고, 배경 판정은 합성 픽셀을 **실제 흰 배경 게이트에 통과시켜** 얻었다.

| 시나리오 | 원본 보존 | 허용 마스크 | HTML 문구 | 보존 영역 | 제외 | 신호 | 사유 |
|---|---|---|---|---|---|---|---|
| 평범형(샘플 1 성격) | O | 3 | 3 | 0 | 0 | **GREEN** | 흰 배경 위 독립 제목·설명만 있었다 |
| 비대칭형(샘플 2 성격) | O | 2 | 2 | 1 | 0 | **YELLOW** | 치수선 숫자는 `keep_raster` 로 원본을 지켰다 |
| 복합형(프리티 성격) | O | 1 | 1 | 2 | 0 | **YELLOW** | 사진 위 카피는 배경이 흰색이 아니라 원본 유지 |
| 예외형(샘플 6 성격) | O | 0 | 0 | 2 | 0 | **RED** | 색 띠 위 카피 + 도해 라벨 — 안전한 자리가 없다 |

**이미지 수와 설명 수가 달라도 문제가 되지 않는다**(비대칭형): 짝맞춤을 하지 않기 때문이다.

| 결함 | 원인 | 교정 |
