# 기본형 본문 라이브 텍스트 오버레이 설계

## 상태

- 사용자 승인: 2026-08-25
- 현재 기준선: `73a3cd4108ca72d8241a507dce7de1d6565126b4`
- 목적: 본문의 원본 이미지·순서·여백을 흔들지 않으면서, 안전하게 지울 수 있는 그림 글자만 HTML 글자로 바꾼다.

## 가장 중요한 결정

본문을 다시 섹션별로 자르고 조립하지 않는다. 현재 성공한 `원본 통이미지 보존`을 정본으로 유지하고, 그 이미지 위에 다음 두 레이어만 얹는다.

1. 원본 글자를 가리는 마스크
2. 같은 내용을 우리 글꼴·색상·크기로 표시하는 HTML 텍스트

이 방식은 원본 사진·도해·선·화살표·이미지 순서·간격을 그대로 보존한다. AI가 섹션 수나 이미지/설명 짝을 맞추지 않으므로, 샘플 2처럼 이미지 수와 설명 수가 달라도 문제가 없다.

## 처리 단위

기존 한 번의 Claude 판독 응답에 본문 글자 영역 장부를 추가한다. 추가 호출이나 섹션별 호출은 만들지 않는다.

```ts
interface BasicBodyTextRegion {
  bandIndex: number;
  rect: { x: number; y: number; width: number; height: number }; // 해당 밴드 기준 0..1
  text: string;
  role: 'heading' | 'body' | 'label';
  action: 'replace' | 'keep_raster';
  reviewNote: string;
}
```

코드는 기존 밴드 출처 장부(`sourceIndex`, `y`)를 이용해 영역을 원본 통이미지 좌표로 되돌린다. AI가 원본 파일을 자르거나 섹션을 조립하지 않는다.

## 단순한 판정 규칙

### 자동 교체(GREEN)

- 흰색 또는 거의 단색인 빈 배경 위에 놓인 제목·설명 문장
- 제품·사람·도해·선·화살표와 떨어져 있어 사각형으로 가려도 시각 정보가 손상되지 않는 글자

처리: 글자 영역만 주변 배경색으로 가리고 HTML 글자를 얹는다.

### 원본 보존 + 손검수(YELLOW)

- 글자가 제품·사람·도해·선·화살표에 닿거나 겹친 경우
- 배경이 그라데이션·질감·사진이라 단색 마스크가 티 나는 경우
- AI 좌표가 범위를 벗어나거나 서로 과도하게 겹치는 경우

처리: 해당 영역은 원본 그대로 둔다. 중복 HTML을 얹지 않고 손검수 사유를 남긴다.

### 수동 처리 권장(RED)

- 샘플 6처럼 글자와 그래픽이 페이지 전체에 강하게 통합된 디자인
- 샘플 3처럼 옵션 수가 많고 본문 대부분이 옵션별 전용 디자인인 경우
- 안전하게 교체할 글자 영역이 거의 없는 경우

처리: 자동 리디자인을 억지로 진행하지 않고 원본을 보존한다.

## 보존하는 그림 글자

치수선 숫자, 도해 내부 라벨, 제품 부위를 직접 가리키는 짧은 표식처럼 그림의 의미를 구성하는 글자는 `keep_raster`로 남겨도 된다. 일반 제목·설명 문장과 구분한다.

## 마스크 방식 — 1차는 흰 배경만

- 생성형 인페인팅은 쓰지 않는다.
- 글자 사각형 바깥의 얇은 테두리 픽셀 중 98% 이상이 RGB 각 245 이상일 때만 `흰색에 가까운 빈 배경`으로 인정한다.
- 인정된 영역만 흰색 사각형으로 가리고 HTML 글자를 얹는다.
- 색 배경·그라데이션·사진·도해는 잘 지우려 하지 않고 원본을 보존한다.
- 마스크·HTML 글자는 원본 이미지와 같은 고정 800px 좌표계 안에 절대 배치한다. HTML 저장과 이미지 저장에서 같은 결과가 나와야 한다.

이 기준은 모든 배경을 처리하려는 최종 규칙이 아니다. 첫 실험에서 원본을 망가뜨리지 않고 실제 GREEN 범위를 재기 위한 보수적인 출발점이다.

## 샘플별 예상 분류

- GREEN 후보: 1, 2, 5, 7, 핑거위글, 글랜스, 프리티
- YELLOW 후보: 4(메인/패키지 선택은 별도 문제), 일부 복합 도해
- RED/수동 후보: 3의 다량 옵션 본문, 6의 고밀도 통합 디자인

이는 상품명 하드코딩이 아니라 결과 신뢰도 분류다. 첫 실험의 신호는 임의 점수 없이 다음처럼 정한다.

- GREEN: 유효한 `replace`가 1개 이상이고 보존·거부 영역이 0개
- YELLOW: 교체 영역과 보존·거부 영역이 함께 있음
- RED: 글자 영역은 검출됐지만 안전하게 교체된 영역이 0개

## 이번에 하지 않는 것

- 본문 섹션 재분할·재배열
- Point 번호 생성
- 이미지와 설명의 1:1 짝맞춤
- 메인·KEY FEATURE·패키지·요약정보·섬네일 변경
- 새 OCR 서비스·새 API 키·새 유료 호출
- Python 이관과 속도 최적화
- 전체 샘플을 한 번에 완성하는 본선 패치

## 첫 실험의 합격 조건

대표 4종(평범형 1, 비대칭형 2, 복합형 프리티, 예외형 6)에 대해 진단 결과만 만든다.

1. 원본 통이미지와 픽셀 크기·순서가 유지된다.
2. 안전한 글자 영역은 마스크 미리보기와 HTML 문구로 나온다.
3. 위험한 영역은 원본이 유지되고 YELLOW/RED 사유가 나온다.
4. 상품당 AI 호출은 여전히 1회이고 재시도는 0회다.
5. 기존 Preview 출력 경로는 바뀌지 않는다.
