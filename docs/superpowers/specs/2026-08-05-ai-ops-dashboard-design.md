# 바나나몰2 AI 운영 현황판 설계

- 작성일: 2026-08-05
- 상태: 사용자 설계 승인 완료, 구현 전 검토 대기
- 목적: 구글 시트를 대체하고 회장과 실무자가 같은 개발 현황을 확인·수정하는 독립 웹사이트를 만든다.

## 1. 목표와 성공 기준

별도 주소로 열리는 회장님용 보고 화면을 만든다. 첫 화면에서 바나나몰2 AI 운영 시스템의 현재 단계, 일정, 오늘 업무, 최근 결과, 다음 계획과 위험요소를 한눈에 이해할 수 있어야 한다.

다음 조건을 모두 만족하면 1차 완성으로 본다.

1. PC 화면에서 A·B·C 세 카드가 한 줄에 보인다.
2. 작은 화면에서는 세 카드가 세로로 자연스럽게 이어진다.
3. 로그인 없이 조회·입력·수정·삭제할 수 있다.
4. 다른 컴퓨터에서 열어도 같은 데이터가 보인다.
5. 사용자가 웹에서 고친 내용과 자동 입력한 내용이 같은 저장소에 남는다.
6. 같은 자동 입력을 다시 보내도 중복 행이 생기지 않는다.
7. 변경 전 기록을 보존하고 삭제 전에는 확인을 받는다.
8. 구글 시트를 읽거나 써야만 작동하는 경로가 없다.

## 2. 범위

### 포함

- 독립 React 웹사이트
- Supabase 공용 데이터베이스
- 회장님용 3단 현황판
- 업무 입력·수정·삭제 화면
- 날짜별·주간·월간 집계
- 자동 기록용 서버 API
- 변경 이력과 삭제 확인
- 빈 상태·저장 중·저장 실패 안내

### 제외

- GODO AI OS 내부 라우트 통합
- 구글 시트 연동
- 로그인·권한·사용자별 화면
- 알림 발송, 이메일, 메신저 연동
- Production 배포와 도메인 연결
- 실제 고도몰 데이터의 자동 수집

Production 배포와 환경변수 설정은 구현·로컬 검증 후 사용자에게 별도 승인을 받아 진행한다.

## 3. 화면 설계

전체 화면은 승인된 시안처럼 흰 배경 위에 A·B·C 세로 카드 세 개를 가로로 놓는다. 각 카드는 둥근 모서리, 옅은 테두리와 그림자, 진한 남색 제목띠, 연한 민트색 소제목 카드로 구성한다. 표의 격자 느낌은 사용하지 않는다.

### A. 전체 현황과 경영 요약

- 현재 단계
- 목표 오픈: 12월 정식 오픈
- 지원 요청 건수
- 7~12월 월·주차별 타임테이블
- 전체 일정 요약 카드
- 회사·타 팀 지원 요청 목록

타임테이블의 각 주는 `전문적인 짧은 제목 + 누구나 이해할 수 있는 한 줄 설명`으로 표시한다.

### B. 일일 업무 캘린더

- 선택한 날짜와 오늘 날짜 표시
- 일일 달력
- 수행 예정 업무
- 수행 업무와 상태
- 이번 주 예정·완료·달성률
- 이번 달 예정·완료·달성률

날짜를 누르면 그 날짜의 예정·수행 업무만 바뀐다.

### C. 최근 업무와 다음 계획

- 현재 진행 업무 설명
- 최근 업무 기록
- 다음 작업 예정(변경될 수 있음)
- 막힌 점·위험요소

현재 진행 업무 설명은 전문용어를 줄이고, 회장님이 읽고 바로 의미를 이해할 수 있는 문장으로 표시한다.

### 편집 화면

기본 화면은 보고서 보기다. 우측 상단 `내용 수정`을 누르면 같은 페이지에서 편집 패널이 열린다.

- 새 업무 추가
- 기존 업무 수정
- 상태 변경
- 일정과 달성률 입력
- 다음 작업·위험요소·지원 요청 입력
- 삭제 전 확인
- 저장 중·저장 완료·저장 실패 상태 표시

## 4. 데이터 구조

### `project_settings`

- 현재 단계
- 목표 오픈 문구
- 현재 진행 업무 설명
- 기준일

### `timeline_weeks`

- 연도·월·주차
- 주차 제목
- 쉬운 설명
- 표시 순서

### `work_items`

- 고유 ID
- 중복 방지 키
- 기준일·예정일·완료일
- 업무 영역·업무 제목
- 상태: 예정 / 진행 중 / 완료 / 보류
- 수행 예정 내용
- 실제 수행 내용
- 결과와 의미
- 다음 작업
- 막힌 점·위험요소
- 회사·타 팀 지원 요청
- 회장님용 한 줄
- 근거 링크
- 달성률
- 생성·수정 시각

### `work_item_revisions`

- 변경 대상 업무 ID
- 변경 전 데이터
- 변경 시각
- 변경 종류: 생성 / 수정 / 삭제

## 5. 데이터 흐름

1. 웹사이트가 서버 API를 통해 Supabase 데이터를 읽는다.
2. 화면은 원본 기록에서 A·B·C에 필요한 요약과 집계를 계산한다.
3. 사용자가 편집하면 서버가 입력을 검증한 뒤 저장한다.
4. 수정·삭제 전에는 기존 내용을 이력 테이블에 보존한다.
5. 저장 성공 후 최신 데이터를 다시 불러와 화면을 갱신한다.

브라우저가 Supabase 관리자 키를 직접 갖지 않는다. 데이터 읽기·쓰기는 웹사이트의 서버 API를 통해서만 한다.

## 6. 자동 입력 규칙

자동 입력은 `POST /api/work-items/upsert` 한 경로를 사용한다.

- 날짜·업무 영역·업무 제목을 바탕으로 안정적인 중복 방지 키를 만든다.
- 같은 키가 없으면 새 기록을 추가한다.
- 같은 키가 있으면 새 행을 만들지 않고 기존 기록을 갱신한다.
- 변경 전 내용은 이력에 남긴다.
- 필수값이 없거나 상태값이 잘못되면 저장하지 않고 쉬운 오류를 반환한다.

이후 사용자가 “오늘 작업을 현황판에 기록해줘”라고 요청하면 같은 형식으로 다음 내용을 보낼 수 있다.

- 오늘 한 일
- 진행 상태
- 결과와 의미
- 다음 작업
- 막힌 점
- 지원 요청

## 7. 공개 편집 정책

사용자 결정에 따라 로그인과 비밀번호를 두지 않는다. 주소를 아는 사람은 조회·입력·수정·삭제할 수 있다.

다만 실수로 인한 손상을 줄이기 위해 다음 경계는 유지한다.

- 모든 입력의 서버 검증
- 삭제 확인창
- 변경 이력 보존
- 중복 방지 키
- 저장 실패 시 기존 화면과 데이터 유지
- 데이터베이스 관리자 키 비노출

## 8. 오류 처리

- 불러오기 실패: 기존 화면을 지우지 않고 재시도 안내
- 저장 실패: 입력 내용을 유지하고 실패 사유 표시
- 중복 요청: 새 행을 만들지 않고 기존 기록 반환
- 잘못된 날짜·상태·달성률: 필드별 안내 후 저장 중단
- 빈 데이터: 오류 화면 대신 시작 안내와 `첫 업무 추가` 표시

## 9. 검증

### 자동검사

- 업무 생성·수정·삭제
- 자동 입력 중복 방지
- 변경 이력 보존
- 날짜별·주간·월간 집계
- 달성률 0건 처리
- 저장 실패 시 기존 데이터 유지
- 공개 화면에 비밀키가 포함되지 않음

### 실제 화면 검사

- PC에서 A·B·C가 한 줄에 표시
- 작은 화면에서 세로 배치
- 긴 타임테이블과 업무 내용이 잘리지 않음
- 편집 후 다른 브라우저에서 같은 내용 확인
- 잘못된 입력과 저장 실패 안내
- 회장님용 설명이 쉬운 문장으로 보임
